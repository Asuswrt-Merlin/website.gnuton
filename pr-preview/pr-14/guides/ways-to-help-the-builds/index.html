Ways to help the builds

#community

GNUton’s builds are a community project. The project source and build logs are public, and the support happens in public threads. There are several useful ways to help, even if you never compile a line of code.

Test a pre-release

Beta builds are how a branch earns its stable release. If you have a supported router and a way back to a known-good image, try a pre-release and report what changed. Include the exact model revision, the build string and the steps that reproduce any problem.

Report bugs clearly

A useful report contains:

  • the router model and hardware revision;
  • the firmware version and branch;
  • what you expected and what happened;
  • reproduction steps, logs and screenshots where relevant;
  • whether the router was updated from stock, stable or another beta.

Use the bug report form so the right details are collected from the start; the form routes to the repository for your firmware line. Feature ideas go through the feature request form.

Send code

Developers can read the project development notes for build instructions and contribution guidance. Changes that stay close to upstream Merlin are the easiest to review and maintain.

Help other owners

Answering a question in Discord, sharing a working configuration on the SNBForums thread, or writing up a fix helps the next person more than you might expect.

Give the project a star

A star on GitHub costs nothing and makes the project easier for other ASUS owners to find.

Firmware changes carry risk. Follow the release notes for your exact model and keep a recovery path available. The project cannot guarantee every flash succeeds.
